# ТОО «PSA» — сайт

Сайт ТОО «PSA» — Полномочного органа Правительства Республики Казахстан по соглашениям о разделе продукции (проекты Кашаган, Карачаганак, Дунга). Три языка: казахский (по умолчанию), русский, английский.

**Репозиторий:** https://github.com/zhzhumabekov/psa-landing
**Состояние на 2026-09-28:** всё закоммичено и запушено (`master` = `origin/master`, последний коммит «Добавлен футер»). Сайт работает только локально — хостинга пока нет.

---

## Коротко: что это технически

- **Django 6.1 + Wagtail 8.0** (CMS), один проект в `backend/`, база **SQLite** (`backend/db.sqlite3`), Python 3.14.
- Сервер сам отдаёт и страницы (шаблоны Django), и статику, и админку. Никакого отдельного фронтенда/сборки нет — обычные `styles.css` и `script.js`.
- **Весь редактируемый контент — в админке Wagtail** (`/admin/`): дерево страниц, библиотеки картинок и документов, настройки подвала.
- **Переключатель языков ҚАЗ / РУС / ENG — на клиенте** (JS), без перезагрузки и без смены адреса: сервер отдаёт все заполненные переводы сразу, скрипт показывает нужный. Выбор запоминается в браузере.

## Установка

Два одинаковых скрипта в папке `backend`: **`install.ps1`** — для Windows, **`install.sh`** — для Ubuntu (и Debian). Оба делают одно и то же:

1. создают виртуальное окружение `venv` (если его ещё нет);
2. ставят пакеты из `requirements.txt`;
3. создают базу `db.sqlite3` и применяют миграции;
4. создают все разделы и подразделы сайта с нужными адресами (`manage.py setup_site`, таблица ниже);
5. спрашивают логин, e-mail и пароль администратора для `/admin/` (если администратора ещё нет).

В конце печатают «Готово» и команду запуска. Если что-то пошло не так — останавливаются и пишут, на каком шаге. Администратора без вопросов (например, на сервере) — заранее задать переменные `DJANGO_SUPERUSER_USERNAME`, `DJANGO_SUPERUSER_PASSWORD` и при желании `DJANGO_SUPERUSER_EMAIL`.

### Windows

Нужны **Python 3.12+** ([python.org](https://www.python.org/downloads/), при установке отметить «Add python.exe to PATH») и Git. В PowerShell:

```powershell
git clone https://github.com/zhzhumabekov/psa-landing.git
cd psa-landing\backend
powershell -ExecutionPolicy Bypass -File install.ps1
```

Путь к папке лучше короткий (например, `C:\Projects\psa-landing`): при очень длинном пути `pip` падает с ошибкой `No such file or directory … Long Path support`.

Запуск сайта:

```powershell
.\venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

### Ubuntu

Нужны **Python 3.12+** и Git. В Ubuntu 24.04 и новее Python подходящий уже есть; в 22.04 — `sudo add-apt-repository ppa:deadsnakes/ppa && sudo apt install python3.12 python3.12-venv`.

```bash
sudo apt install git            # если git ещё нет
git clone https://github.com/zhzhumabekov/psa-landing.git
cd psa-landing/backend
bash install.sh
```

Если в системе нет пакета `python3.X-venv` (в чистой Ubuntu его обычно нет), скрипт предложит поставить его через `sudo apt`; если отказаться или sudo недоступен — создаст `venv` без него и поставит pip официальным `get-pip.py`.

Запуск сайта:

```bash
venv/bin/python manage.py runserver 127.0.0.1:8000
```

Чтобы сайт открывался с других компьютеров сети — `venv/bin/python manage.py runserver 0.0.0.0:8000` и добавить адрес сервера в `ALLOWED_HOSTS` (`psa_backend/settings.py`). Это сервер для разработки, не для публичного хостинга.

### Сайт и админка

Сайт — http://127.0.0.1:8000/, админка — http://127.0.0.1:8000/admin/ (логин и пароль — те, что ввели при установке).

Чтобы сразу перенести записи и файлы «Закупок» с psa.kz (~310 МБ, несколько минут):

```bash
powershell -ExecutionPolicy Bypass -File install.ps1 -ImportProcurement   # Windows
bash install.sh --import-procurement                                      # Ubuntu
```

### Что создаётся в базе

| Раздел | Подразделы (адрес) |
|---|---|
| Закупки `/procurement/` | Контактные лица `/procurement/contacts/`, Архив `/procurement/archive/`, Объявления `/procurement/announcements/`, Особый порядок `/procurement/special-procedure/` |
| Маркетинг `/marketing/` | Предстоящие `/marketing/future/`, Архив `/marketing/archive/` |
| Проекты `/projects/` | Кашаган, Карачаганак, Дунга |
| Местное содержание `/local-content/`, Новости `/news/` | — |

Подразделы создаются пустыми — записи добавляются в админке (или импортом с psa.kz для «Закупок»). Список разделов — в `backend/content/site_tree.py`.

### После `git pull`

Тот же скрипт — он безопасен при повторном запуске (ставит новые пакеты, применяет новые миграции, ничего не удаляет):

```bash
powershell -ExecutionPolicy Bypass -File install.ps1   # Windows
bash install.sh                                        # Ubuntu
```

### Если случайно удалили раздел в админке

В Wagtail нет корзины — удалённая страница удаляется вместе со всеми записями внутри. Сам раздел (или подраздел) с правильным адресом вернёт команда (в Ubuntu вместо `.\venv\Scripts\python.exe` — `venv/bin/python`):

```powershell
.\venv\Scripts\python.exe manage.py setup_site --dry-run   # сначала посмотреть, что будет сделано
.\venv\Scripts\python.exe manage.py setup_site             # создать недостающее
```

Она же чинит адрес, если подраздел создали заново вручную и адрес получился другим (`arxiv` вместо `archive`): без правильных адресов `announcements` / `archive` / `future` не появляются кнопки «Перенести в архив». Записи, удалённые вместе с разделом, команда не восстанавливает — только из резервной копии базы (`db.sqlite3`), поэтому перед большими правками копию лучше сделать.

Ручная установка по шагам (Git Bash) — в [backend/README.md](backend/README.md#установка).

## Сервер (Docker)

Для выкладки на сервер — контейнеры: сайт (Django + gunicorn) и **Caddy**, который сам выпускает и продлевает HTTPS-сертификат Let's Encrypt, раздаёт статику и загруженные файлы. База SQLite и загруженные файлы — в томе Docker, переживают пересборку и обновления.

### Установка одной командой

Нужен сервер **Ubuntu 22.04+ / Debian 12+** с открытыми портами 80 и 443 и, для HTTPS, домен, DNS-запись которого (A-запись) уже указывает на IP сервера.

```bash
git clone https://github.com/zhzhumabekov/psa-landing.git
cd psa-landing
sudo bash deploy/install.sh
```

Скрипт:

1. ставит Docker, если его нет;
2. спрашивает домен (например, `psa.kz, www.psa.kz`; пусто — сайт по IP без HTTPS) и создаёт файл настроек `.env` со случайным секретным ключом;
3. открывает порты 80/443 в брандмауэре `ufw`, если он включён;
4. собирает и запускает контейнеры; при старте сайта сами выполняются миграции базы, сборка статики и `setup_site` (все разделы с нужными адресами);
5. ждёт, пока сайт ответит, и спрашивает логин и пароль администратора (если его ещё нет).

`sudo bash deploy/install.sh --import-procurement` — то же и перенос «Закупок» с psa.kz. Без вопросов (CI и т.п.) — задать заранее `SITE_DOMAINS`, `DJANGO_SUPERUSER_USERNAME`, `DJANGO_SUPERUSER_PASSWORD`.

### Обновление

```bash
cd psa-landing
git pull
sudo bash deploy/install.sh
```

Повторный запуск пересобирает и перезапускает контейнеры; `.env`, база и файлы не трогаются, новые миграции применяются сами.

### Повседневное (из папки проекта)

| Что | Команда |
|---|---|
| логи сайта | `docker compose logs -f web` |
| режим обслуживания (503) | админка → «Настройки» → «Сайт», или `docker compose exec web python manage.py maintenance on` (`off` — выключить) |
| сменить пароль администратора | `docker compose exec web python manage.py changepassword admin` |
| любая команда Django | `docker compose exec web python manage.py <команда>` |
| перезапустить | `docker compose restart` |
| остановить | `docker compose down` (данные сохраняются) |

### Резервные копии

```bash
sudo bash deploy/backup.sh
```

Создаёт `backups/psa-<дата>.tar.gz`: база (копируется штатно, без остановки сайта) и загруженные файлы. Копии стоит забирать с сервера. Для ежедневной копии — строка в `sudo crontab -e`: `0 3 * * * cd /путь/к/psa-landing && bash deploy/backup.sh`.

Восстановление (текущие данные заменяются; перед этим скрипт сам делает копию текущего состояния):

```bash
sudo bash deploy/restore.sh backups/psa-<дата>.tar.gz      # из резервной копии
sudo bash deploy/restore.sh db.sqlite3 media                # перенести базу (и файлы) с локального компьютера
```

Для переноса контента с локального компьютера — скопировать на сервер `backend/db.sqlite3` (и папку `backend/media`, если в ней есть загруженные файлы), затем вторая команда.

### Настройки (`.env`)

Файл `.env` в корне проекта создаёт `install.sh`; образец со всеми параметрами — [`.env.example`](.env.example). Главное: `SITE_ADDRESS` (домены для Caddy), `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS`, `DJANGO_HTTPS`. После правки `.env` — `docker compose up -d`. Почта, получатели формы «Контакты» и режим обслуживания — не в `.env`, а в админке (см. [«Настройки сайта в админке»](#настройки-сайта-в-админке)).

Без переменных окружения (локальная разработка) всё работает как раньше: `DEBUG` включён, база и файлы — в `backend/`.

### Файлы

| Файл | Что |
|---|---|
| `docker-compose.yml` | два контейнера (`web`, `caddy`) и тома данных |
| `backend/Dockerfile`, `backend/docker-entrypoint.sh` | образ сайта; при старте — миграции, статика, `setup_site`, затем gunicorn |
| `deploy/Caddyfile` | HTTPS, статика (`/static/`), файлы (`/media/`, кроме `media/documents/` — документы отдаёт Django по `/files/`), остальное — сайту |
| `deploy/install.sh`, `deploy/backup.sh`, `deploy/restore.sh` | установка/обновление, резервная копия, восстановление |
| `.env.example` | образец настроек |

**HSTS не включён** намеренно (`manage.py check --deploy` о нём предупреждает): его стоит включать, только когда HTTPS на домене точно работает — браузеры запоминают его надолго, откатить нельзя. Перенаправление http → https Caddy делает сам.

## Форма «Контакты» и обращения

Форма на главной отправляет обращение на сервер (`POST /contact/`, `content/contact.py`):

1. обращение **сохраняется** — админка → **«Обращения»**: список (новые сверху), поиск по имени, e-mail и тексту, фильтры «Прочитано» / «Письмо отправлено» / по дате. Открытое обращение само помечается прочитанным (галочку можно снять). Вручную обращения не создаются — только с сайта;
2. уходит **письмо** на адреса из «Настройки» → «Форма «Контакты»» — с именем, e-mail, языком сайта, текстом и ссылкой на обращение в админке; «Ответить» в почте отвечает сразу посетителю (Reply-To).

Если письмо не ушло (не указаны получатели, SMTP не настроен или недоступен) — обращение всё равно сохранено, посетитель видит «Спасибо! Сообщение отправлено», а в обращении — «Письмо отправлено: нет» и текст ошибки. Защита от спама: скрытое поле-ловушка для ботов и не больше 5 обращений за 10 минут с одного IP.

## Настройки сайта в админке

«Настройки» в меню админки:

| Пункт | Что там |
|---|---|
| **Почта (SMTP)** | почтовый сервер, порт, шифрование (STARTTLS / SSL / нет), логин, пароль, адрес и имя отправителя; кнопка **«Отправить тестовое письмо»** — показывает ответ сервера при ошибке. Для Gmail / Mail.ru / Яндекса нужен «пароль приложения». Пусто — письма только пишутся в лог сервера |
| **Форма «Контакты»** | кому отправлять обращения (несколько адресов — с новой строки или через запятую), тема письма |
| **Сайт** | режим обслуживания (503) |
| **Подвал сайта** | название, адрес, телефоны, e-mail, «Корпоративная почта» |

Изменения действуют сразу, перезапуск не нужен. В `.env` (сервер) остаётся только то, без чего сайт не запустится: домены, секретный ключ, HTTPS.

Пароль почты хранится в базе сайта открытым текстом (как у любых настроек Wagtail) — видят его только пользователи с доступом к этим настройкам; лучше завести для сайта отдельный ящик или «пароль приложения», а не личный пароль.

## Оформление админки

Админка Wagtail оформлена как сайт: синие кнопки и ссылки, золотые акценты, шрифты PT Sans / PT Serif, логотип PSA, значок вкладки с узором. Работают обе темы Wagtail — выбираются в профиле («Аккаунт» → тема), по умолчанию как в системе:

- **светлая** — белое боковое меню и оригинальный логотип с чёрными буквами;
- **тёмная** — стандартное тёмное меню Wagtail, логотип со светлыми буквами, ссылки светлее.

- цвета и шрифты — `backend/static/psa-admin.css` (переопределяет CSS-переменные Wagtail, подключается хуком в `content/wagtail_hooks.py`);
- логотип, заголовок вкладки «… - PSA», значок — `backend/templates/wagtailadmin/base.html`, `psa_logo.html`;
- страница входа («Вход в админку ТОО «PSA»») — `backend/templates/wagtailadmin/login.html`.

Кнопки сделаны синими, а не золотыми намеренно: белый текст на золотом плохо читается (контраст ~2.8:1 при норме 4.5:1).

## Страницы ошибок и режим обслуживания

Свои страницы на трёх языках — `backend/templates/400.html`, `403.html`, `404.html`, `500.html`, `503.html`:

- **403, 404** — в оформлении сайта (шапка с меню, подвал из админки). Тексты kz/en — ключи `error_page.*` в `static/script.js`.
- **400, 500, 503** — облегчённые (`templates/errors/standalone.html`): без меню и без обращений к базе, чтобы открывались, даже когда сломалась база или сервер. Тексты kz/en — словарь прямо в `standalone.html`.

Django показывает их только при `DEBUG = False`. В режиме разработки (`DEBUG = True`, как сейчас) вместо них — отладочные страницы Django, а свои можно посмотреть по адресам http://127.0.0.1:8000/_errors/404/ (и `400`, `403`, `500`, `503`).

**Режим обслуживания (503)** — посетители видят «Сайт на техническом обслуживании», админка работает, а вошедшие в админку сотрудники видят сайт как обычно (можно проверить изменения до открытия). Включается в админке — **«Настройки» → «Сайт» → «Режим обслуживания»**, или командой:

```powershell
.\venv\Scripts\python.exe manage.py maintenance on       # включить (Ubuntu: venv/bin/python …)
.\venv\Scripts\python.exe manage.py maintenance off      # выключить
.\venv\Scripts\python.exe manage.py maintenance status   # проверить
```

Перезапуск сервера не нужен — это настройка в базе, галочка в админке и команда меняют одно и то же.

```bash
cd backend

```

- Сайт — http://127.0.0.1:8000/
- Админка — http://127.0.0.1:8000/admin/ (логин `admin`, пароль сменён владельцем — первоначальный из старых версий README больше не действует; сбросить: `./venv/Scripts/python.exe manage.py changepassword admin`)

## Как редактировать (админка)

- **«Страницы»** → «Главная» → раздел → «Добавить дочернюю страницу» → заполнить → «Опубликовать». Есть черновики, история версий, предпросмотр.
- **Вкладки «Русский / Қазақша / English»** у записей всех разделов: русский — основной; если перевод не заполнен, на сайте показывается русский.
- **Текст собирается из блоков** (кнопка «+»): «Текст» (обычный редактор), «Таблица» (как в Excel), «Markdown», «HTML».
- **Картинки и файлы** — библиотеки «Изображения» и «Документы». У записей «Закупок» отдельное поле «Файлы» (общее для всех языков).
- **Закупки и Маркетинг: «Перенести в архив» / «Вернуть в объявления» («… в предстоящие»)** — в меню «…» у записи в списке, в меню «…» редактора и рядом с «Опубликовать».
- **Адреса разделов не менять**: `home`, `projects`, `local-content`, `procurement`, `marketing`, `news`, а в «Закупках» — `announcements` и `archive`, в «Маркетинге» — `future` и `archive`. На них завязаны меню и кнопки переноса.

## Закупки и перенос с psa.kz

Раздел заполнен с psa.kz/zakupki/ командой `manage.py import_psa_procurement`: 560 записей (архив с 2011 года), 357 файлов (~310 МБ, в `backend/media/`, не в git), казахские версии там, где они есть на psa.kz. **Повторный запуск с `--replace` стирает всё, что правили в «Закупках» вручную** — после начала ручного редактирования не запускать. Подробнее — [backend/README.md](backend/README.md), раздел «Закупки».

## Не сделано / известные ограничения

- **Хостинга пока нет**, но проект к нему готов — см. [«Сервер (Docker)»](#сервер-docker). Сборка контейнера и выпуск сертификата на настоящем сервере ещё не проверялись (на машине разработки нет Docker): проверена та же схема без Docker — gunicorn за Caddy с этими же настройками. Старая статическая версия на Vercel (`psa-landing-gold.vercel.app`) к текущему коду не относится.
- **База и файлы не в git** (`db.sqlite3`, `media/`) — весь контент, внесённый в админке, и 310 МБ файлов «Закупок» существуют только на этой машине. Делать резервные копии; для переноса на сервер — копировать оба.
- **Форма «Контакты» на главной никуда не отправляет** — только проверяет поля в браузере.
- **Главная не редактируется из админки**, и блок «Проекты» на ней — отдельная статичная копия текстов (раздел `/projects/` — в админке). Можно подключить главную к админке.
- **Переводы:** у партнёров на главной нет kz/en; казахские и английские тексты, добавленные в `script.js` (заголовки разделов, служебные надписи), стоит проверить носителю языка. `<title>` страниц переключателем языка не меняется.
- Раздела «Документы» и «Новости» на psa.kz пока не переносили — там тестовые записи из `seed.py`.
