# Бэкенд на Django + Wagtail (локальный запуск)

Сайт — Django-проект с CMS [Wagtail](https://wagtail.org/) 8.0. SQLite внутри (файл `db.sqlite3`, создаётся `migrate`), всё поставлено в venv — ничего не устанавливалось глобально.

## Запуск

```bash
cd backend
./venv/Scripts/python.exe manage.py runserver 127.0.0.1:8000
```

Сайт — http://127.0.0.1:8000/, админка Wagtail — http://127.0.0.1:8000/admin/.

## Дерево страниц

Весь контент — страницы Wagtail в одном дереве (админка → «Страницы»):

```
Главная (HomePage)                          /
├── Проекты (ProjectsIndexPage)                 /projects/
│   └── проекты (ProjectPage)                   /projects/kashagan/ и т.д.
├── Местное содержание (LocalContentIndexPage)  /local-content/
│   └── записи (LocalContentPage)               /local-content/<slug>/
├── Закупки (ProcurementIndexPage)              /procurement/
│   └── подразделы (ProcurementSectionPage)     /procurement/announcements/ и т.д.
│       └── записи (ProcurementPage)            /procurement/announcements/<slug>/
├── Документы (DocumentsIndexPage)              /documents/
│   └── записи (DocumentPage)                   /documents/<slug>/
└── Новости (NewsIndexPage)                     /news/
    └── записи (NewsPage)                       /news/<slug>/
```

- Главная и 4 раздела создаются автоматически миграцией `content/migrations/0002_create_site_tree.py`, раздел «Проекты» с Кашаганом, Карачаганаком и Дунгой — `0006_create_projects.py` (тексты перенесены из модалок главной: описание — блок «Текст», факты — блок «Таблица»). Каждый раздел может быть только один (`max_count = 1`), внутри раздела можно создавать только записи своего типа.
- Чтобы добавить запись: «Страницы» → раздел → «Добавить дочернюю страницу» → заполнить → «Опубликовать». Запись сразу появится в списке раздела (сортировка по дате, у закупок — по сроку подачи). Черновики, отложенная публикация, история версий и предпросмотр — стандартные возможности Wagtail.
- Slug (часть адреса) Wagtail генерирует из заголовка сам, транслитом в латиницу (`WAGTAIL_ALLOW_UNICODE_SLUGS = False`), его можно поменять на вкладке «Продвижение». Там же — SEO-заголовок и описание для `<meta description>`.
- **Slug'и разделов (`projects`, `local-content`, `procurement`, `documents`, `news`) и главной (`home`) не менять** — на них завязано меню в `templates/base.html` (`{% slugurl %}`).
- Выпадающее меню «Проекты» строится из опубликованных страниц раздела «Проекты» (тег `menu_projects`, `content/templatetags/navigation.py`) — новый проект появится в меню сам, порядок — как в дереве страниц админки (меняется перетаскиванием). У проекта нет даты; поля — регион, «кратко» (подпись на карточке) и описание блоками.
- **Блок «Проекты» на главной (карточки + всплывающие окна) — отдельный и статичный**: тексты в `templates/index.html` и `projectDetails` в `static/script.js`, из админки не редактируется. Меню на него больше не ссылается (якоря `#kashagan` и т.п. убраны), кнопка «Наши проекты» в Hero по-прежнему прокручивает к нему.

## Закупки

Устроены как psa.kz/zakupki/: страница «Закупки» — карточки подразделов, подразделы — **Контактные лица, Архив, Объявления, Особый порядок осуществления закупок** (порядок — как в дереве страниц админки). В каждом подразделе — список записей (новые сверху, без даты — в конце, по 20 на страницу), слева — меню подразделов (на телефоне — вкладки сверху). Подраздел можно добавить/переименовать/удалить в админке, как обычную страницу.

Запись (`ProcurementPage`): дата, текст (блоки: текст, таблица, Markdown, HTML), **«Файлы»** — документы из библиотеки, общие для всех языков, выводятся списком с типом и размером файла. (Полей «Статус», «Срок подачи» и «Ссылка на тендерную площадку» нет — убраны по просьбе, миграция `0009`.) Контактные лица — тоже записи (ФИО — заголовок, должность/телефон/e-mail — в тексте).

**Объявление → архив и обратно.** У записей подразделов «Объявления» и «Архив» в админке есть пункт **«Перенести в архив»** / **«Вернуть в объявления»** — в меню «…» у записи в списке страниц, в меню «…» в шапке редактора и в меню рядом с «Опубликовать». После подтверждения запись перемещается (штатное перемещение Wagtail: проверка прав, запись в журнале, новый адрес страницы; опубликованность и черновик не меняются). Если в назначении уже есть запись с таким же адресом, к slug добавляется `-2`, `-3`…; при возврате суффикс снимается, и адрес восстанавливается. Логика — `content/procurement_transfer.py`, кнопки — `content/wagtail_hooks.py`; пары подразделов определяются по slug `announcements` ↔ `archive`, поэтому **эти slug не менять**.

**Контент перенесён с psa.kz** командой:

```bash
./venv/Scripts/python.exe manage.py import_psa_procurement            # если подразделов ещё нет
./venv/Scripts/python.exe manage.py import_psa_procurement --replace  # удалить текущие подразделы и файлы коллекции «Закупки», импортировать заново
```

560 записей (архив — 555, с 2011 года), 357 файлов (~310 МБ) — в библиотеке «Документы», коллекция «Закупки». Казахские заголовки/тексты — с psa.kz/kz/ для контактов, объявлений и «Особого порядка» (архив на psa.kz только по-русски), английских на psa.kz для этих разделов нет. Одинаковые файлы под разными ссылками (ru/kz) склеиваются в один документ по содержимому. Один файл, на который ссылается архив psa.kz, там самом отсутствует (404) — пропущен. **`--replace` затирает правки, сделанные в админке в «Закупках»** — после начала ручного редактирования команду больше не запускать. Страницы и файлы psa.kz кэшируются во временной папке (`--cache-dir`), повторный запуск ничего не качает заново. HTTPS — через системные сертификаты (`truststore`).

## Языки (kz / ru / en)

У записей всех четырёх разделов в редакторе вкладки **«Русский» / «Қазақша» / «English»** (+ «Продвижение»). Русский — основной (обязательные поля, из русского заголовка делается адрес страницы); в «Қазақша» и «English» — переводы заголовка, основного текста (те же блоки, что и в русском: текст, таблица, Markdown, HTML), а у новостей и документов — краткого описания и категории. Дата, файлы и ссылки — общие для всех языков, во вкладках перевода их нет.

На сайте сервер отдаёт все заполненные переводы сразу, а переключатель ҚАЗ/РУС/ENG в шапке показывает нужный (`applyContentLanguage` в `static/script.js`, разметка — теги `ml`, `ml_blocks`, `ml_preview`, `ml_date` из `content/templatetags/multilang.py`). **Если перевод не заполнен — показывается русский вариант.** Даты выводятся на языке сайта («28 қыркүйек 2026 ж.» / «28 сентября 2026 г.» / «28 September 2026»).

Модели: у переводимого поля есть копии `<поле>_kz` и `<поле>_en` (`title_kz`, `body_en`…), список таких полей — `translated_fields` в модели, вкладки строит `TranslatedPage.build_edit_handler()` (`content/models.py`). Чтобы сделать переводимым ещё одно поле — добавить обе копии в модель, имя в `translated_fields`, `makemigrations`, и в шаблоне выводить через `{% ml page "поле" %}`.

Тексты главной (Hero, О компании, Проекты, Партнёры, Контакты), заголовки/подводки разделов и служебные надписи («Читать полностью →», «Пока нет…») — не в админке, а в шаблонах; их переводы — словарь `translations` в `static/script.js`. `<title>` и `<meta description>` страниц — только по-русски/по-казахски, как были, переключателем не меняются.

## Форматированный текст, таблицы, картинки, документы

Поля `body` (Местное содержание, Новости) и `description` (Закупки) — `StreamField`: текст собирается из блоков, кнопка «+» в редакторе добавляет новый блок, блоки можно менять местами, дублировать и удалять. Типы блоков (`content/blocks.py`):

| Блок | Для чего |
|---|---|
| **Текст** | Обычный редактор (Draftail): заголовки, жирный/курсив, списки, ссылки, картинки, видео по ссылке |
| **Таблица** | Визуальный редактор таблиц: клетки редактируются двойным кликом, строки/колонки и объединение ячеек — правой кнопкой мыши. «Заголовки таблиц» — какая строка/колонка шапка, «Заголовок таблицы» — подпись над таблицей |
| **Markdown** | Текст в Markdown, в том числе таблицы: `\| Колонка 1 \| Колонка 2 \|`, под шапкой `\| --- \| --- \|` |
| **HTML** | Готовый HTML-код (например, таблица, скопированная из другого места) — вставляется как есть, без проверки |

В шаблонах поля выводятся через `{% include_block page.body %}`, каждый блок — в обёртке `.content-block--<тип>` (широкие таблицы прокручиваются по горизонтали, а не ломают страницу на телефоне). В списках разделов превью строится только из блоков «Текст» и «Markdown», без таблиц (`text_preview` в `content/blocks.py`).

- **Картинки** загружаются в библиотеку «Изображения» (прямо из редактора или отдельно), Wagtail сам делает уменьшенные копии под формат («Во всю ширину» / «Слева» / «Справа»). Файлы — в `media/images/` и `media/original_images/`.
- **Документы** (файлы для раздела «Документы») — в библиотеке «Документы»; у записи `DocumentPage` можно выбрать файл оттуда или указать внешнюю ссылку. Раздаются по адресу `/files/<id>/<имя>` (не `/documents/` — этот адрес занят страницей раздела). Разрешённые расширения и лимит размера — `WAGTAILDOCS_EXTENSIONS` / `WAGTAILDOCS_MAX_UPLOAD_SIZE` в `settings.py`.

Блоки «Текст» и «Таблица» Wagtail при сохранении сам чистит от лишнего HTML. **«Markdown» и «HTML» выводятся без очистки** (в них можно вставить в том числе `<script>`) — это допустимо, пока писать в админку могут только доверенные пользователи. Если когда-то появятся редакторы, которым нельзя доверять код, эти два блока стоит убрать из `ContentBlocks`.

## Структура

```
backend/
├── venv/                 — виртуальное окружение (не в git)
├── manage.py
├── requirements.txt      — зафиксированные версии (Django, Wagtail и зависимости)
├── seed.py               — по одной примерной записи в каждый раздел (опционально)
├── templates/
│   ├── base.html                  — общая шапка/меню/подвал/модалка проектов
│   ├── index.html                 — главная (HomePage)
│   ├── local_content.html, procurement.html, documents.html, news.html
│   │                              — списки разделов (*IndexPage)
│   ├── local_content_detail.html, procurement_detail.html, document_detail.html, news_detail.html
│   │                              — страницы записей
│   └── blocks/content_blocks.html — вывод блоков StreamField
├── static/
│   ├── styles.css        — стили
│   └── script.js         — мобильное меню, модалки проектов, i18n, форма, path-aware плавный скролл
├── psa_backend/          — настройки, корневые urls (/admin/, /files/, всё остальное — Wagtail)
└── content/              — приложение: модели страниц + миграции
    ├── models.py         — HomePage, 4 *IndexPage и 4 типа записей
    ├── blocks.py         — блоки StreamField: текст, таблица, Markdown, HTML
    ├── wagtail_hooks.py, procurement_transfer.py — кнопки «Перенести в архив» / «Вернуть в объявления»
    ├── templatetags/     — multilang.py (вывод переводов: ml, ml_blocks, ml_preview, ml_date), navigation.py (меню «Проекты»)
    └── management/commands/import_psa_procurement.py — перенос «Закупок» с psa.kz
```

`db.sqlite3` и `media/` (загруженные картинки и документы) — не в git, это данные, не код (см. `.gitignore`).

## Восстановить с нуля (новая машина / потеряли venv)

```bash
cd backend
python -m venv venv
./venv/Scripts/pip.exe install -r requirements.txt
./venv/Scripts/python.exe manage.py migrate      # создаст и дерево страниц
DJANGO_SUPERUSER_USERNAME=admin DJANGO_SUPERUSER_EMAIL=admin@psa.local DJANGO_SUPERUSER_PASSWORD="НОВЫЙ_ПАРОЛЬ" ./venv/Scripts/python.exe manage.py createsuperuser --noinput
./venv/Scripts/python.exe seed.py   # опционально, тестовые записи для проверки
```
