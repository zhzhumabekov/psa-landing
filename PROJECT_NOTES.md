## Текущее фактическое состояние

Ровно 4 файла в проекте, больше ничего: `index.html`, `styles.css`, `script.js`, `README.md` (+ `.gitignore`, `.vercel/`).

Одна страница (`index.html`), секции по порядку: Header → Hero → О компании → Проекты (3 карточки + модалки на `<dialog>`) → Партнёры (7 карточек-ссылок) → Контакты (форма с валидацией). Никакого бэкенда, никакой отдельной админки, никаких других HTML-страниц.

**Язык по умолчанию — русский** (`currentLang = "ru"`, `<html lang="ru">`, активна кнопка РУС). Это важно: в проекте БЫЛ этап, когда казахский стал языком по умолчанию (коммит `fbb8235`), но пользователь откатил именно до состояния ПЕРЕД этим — то есть казахский-по-умолчанию сейчас **не действует**, если понадобится — это отдельная, уже решённая один раз задача (см. «История» ниже), можно переделать так же: `currentLang = "kz"` в script.js + `<html lang="kz">`/активная ҚАЗ-кнопка в index.html + перевести `<title>`/`<meta description>` (они не завязаны на JS-i18n, их руками).

**Переводы неполные**: у `kz` и `en` блоков в `script.js` нет ключей `partner.*` (только `partners.eyebrow`/`partners.title`, сами карточки партнёров не переведены) — работает откат `translate()` на `ru` (`translations[currentLang][key] || translations.ru[key] || key`), так и задумано, не баг.

**Известный неисправленный баг:** пункты меню «Местное содержание / Закупки / Документы / Новости» ведут на `#local-content`/`#procurement`/`#documents`/`#news` — секций с такими id на странице нет, клик тихо ничего не делает (JS плавного скролла просто не находит цель и молча выходит). Это чинили дважды в этой сессии (отдельными страницами + PocketBase-бэкендом) — оба раза пользователь откатывал результат целиком. **Не чинить самостоятельно без прямой просьбы** — похоже, направление решения пока не устраивает, нужно сначала обсудить подход, не бросаться переделывать.

## Как я проверяю UI

`chromium-cli` в этом окружении недоступен. Паттерн: локальный `python -m http.server <port>` + `npm install --no-save playwright@1.63.0` + `npx playwright install chromium` (один раз качает ~115MB) + инлайновые `node -e "import('playwright')..."` скрипты. **Важно:** `lsof -ti:PORT | xargs kill` в этом Git-Bash-on-Windows **не работает надёжно** — в одном случае оставил 6 висящих `python.exe` за несколько ответов подряд, каждый на своём порту. Правильный способ остановить процесс на Windows из этого Bash: найти PID через `netstat -ano | grep LISTENING`, проверить, что это ожидаемый процесс (`tasklist //FI "PID eq <pid>"`), затем `taskkill //F //PID <pid>`.

## Грабли, на которые уже наступал (актуально, если делать похожие вещи снова)

- **`[hidden]` перебивается CSS того же уровня специфичности**, если у элемента есть класс с `display:flex/block` — правило класса может победить (одинаковая специфичность, но позже в каскаде). Чинится явным `.selector[hidden] { display: none; }`.
- **`.parent ul` (descendant selector) ловит и вложенные `<ul>`** — например, дропдаун «Проекты» внутри `.main-nav` случайно наследовал `display:flex` от общего правила навигации. Использовать `.main-nav > ul` (прямой потомок) — этот фикс, кстати, единственный из «навигационных» уже закреплён в текущем состоянии (`c16f55e`), не откатился.
- **Hero был «кривым»** из-за двойного назначения класса `.container` (даёт `margin-inline:auto`) + свой `max-width` на одном и том же элементе — центрировался отдельно от остальных секций. Разделять: внешний `.container` для паддингов/центрирования, внутренний элемент — только ограничение ширины текста, без своего `margin:auto`.
- **`<title>`/`<meta description>` не подключены к i18n-системе** (`translate()`/`data-i18n` их не трогает) — при смене языка по умолчанию их обновлять вручную отдельно.
- **PocketBase-специфика (если снова возьмём этот бэкенд):** `editor`-поля хранят HTML из доверенного источника (только суперюзер через `/_/`) — их можно рендерить через `innerHTML` осознанно; для полей, куда потенциально сможет писать кто-то ещё (форма на сайте, не через админку) — только `textContent`. PocketBase не работает как SQLite-файл на Vercel serverless (нет постоянной ФС) — нужен отдельный постоянный хост с диском (или сам локальный запуск, как было здесь).
